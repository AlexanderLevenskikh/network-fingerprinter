# Network Fingerprinter — руководство пользователя

[Русский](USERGUIDE.ru.md) · [English](USERGUIDE.md) · [Обзор проекта](README.ru.md) · [Эксплуатация Docker](docs/docker.md)

Это пошаговое руководство для **локального пассивного анализа трафика**: запустить сервисы, войти в Analyst, импортировать PCAP, открыть TCP-потоки и изучить доступные TCP/TLS/HTTP-отпечатки. **Обычный запуск не перехватывает трафик вашей сети.** Для знакомства не нужны физический сетевой интерфейс или настройка Kibana.

> **Важно:** анализируйте только те PCAP и интерфейсы, на работу с которыми у вас есть разрешение. Это локальный демонстрационный стенд, не защищённое production-развёртывание. При импорте наблюдения из пакетов сохраняются в Elasticsearch.

## 1. Требования и запуск

- Docker Engine с Compose v2. В Windows/macOS — Docker Desktop в режиме **Linux-контейнеров**. Основная сквозная проверка выполнена на Linux в CI.
- Не менее **4 ГиБ** памяти для Docker. На компьютере должны быть свободны порты **3000**, **5601**, **9200**.
- Git для клонирования проекта. Python 3 нужен только для создания синтетического тестового PCAP.

В PowerShell, Bash или другом терминале:

~~~sh
git clone https://github.com/AlexanderLevenskikh/network-fingerprinter.git
cd network-fingerprinter
docker compose --env-file .env.example up -d --build
docker compose --env-file .env.example ps -a
~~~

Дождитесь состояния **healthy** у `analyst`, `postgres`, `elasticsearch` и `kibana`. Одноразовые задачи `elastic-init` и `kibana-init` должны **завершиться с кодом 0**, а не работать постоянно. Первый запуск может потребовать времени на загрузку образов и инициализацию ES. Если есть ошибки — см. [Диагностику](#7-диагностика).

Команды выше используют **демонстрационные пароли** и не создают конфигурацию. В этом режиме добавляйте `--env-file .env.example` ко **всем последующим** командам Compose.

Для постоянного *локального* стенда **до первого запуска с пустой БД** скопируйте `.env.example` в игнорируемый Git файл `.env` (`Copy-Item .env.example .env` в PowerShell или `cp .env.example .env` в Bash), замените **все** примерные пароли и `SESSION_SECRET`, затем выполните `docker compose up -d --build`. Если БД уже создана, изменение `APP_ADMIN_PASSWORD` **не изменит** пароль существующего пользователя.

## 2. Вход в Analyst

Откройте **http://127.0.0.1:3000**. Для **пустого тома PostgreSQL** при запуске с `.env.example`:

| Поле | Демонстрационное значение |
| --- | --- |
| Логин | `admin` |
| Пароль | `local-admin-change-me` |

Это значения **только для локального теста**. Входа `root/root` по умолчанию **нет**. Если база уже существовала, используйте её действующие учётные данные. При потере пароля см. [адресное восстановление администратора](docs/SECURITY_AUDIT.md#recover-an-existing-administrator-without-deleting-data).

В меню находятся **«Загрузка *.pcap»**, **«Потоки»**, **«Статистика»** (по клиентам / по серверам). Создавать и удалять пользователей может только администратор; обычный пользователь не имеет доступа к управлению учётными записями.

## 3. Импорт файла PCAP

1. В меню выберите **«Загрузка *.pcap»** (экран Player).
2. Перетащите один или несколько файлов `.pcap` или выберите их нажатием. Ограничение — **10 МиБ на каждый файл**, а не на весь набор.
3. Проверьте **отдельный статус каждого файла**:

   | Статус | Что означает |
   | --- | --- |
   | **Обрабатывается…** | Файл загружается и декодируется; результат ещё не готов |
   | **Проиндексировано пакетов: N** | Подтверждено N успешных операций записи в Elasticsearch |
   | **Файл корректен, подходящих пакетов нет** | Импорт успешен, но нужные типы пакетов отсутствуют; нового потока может не быть |
   | **Ошибка импорта: …** | Ошибка формата, размера, сервера или сети; успешным импортом это не считается |

Импортируются выбранные наблюдения: **TCP SYN/SYN-ACK**, **TLS ClientHello**, **HTTP-запросы/ответы**. Система не индексирует *все* пакеты файла. Повреждённый PCAP или файл сверх лимита отклоняется; это **не** тот же случай, что корректный файл с результатом 0. После ошибки можно выбрать другой файл — поле загрузки не блокируется.

**Постоянной истории загрузок в интерфейсе нет**, но сами индексированные наблюдения сохраняются в Elasticsearch. Повторная загрузка может добавить наблюдения снова. Массовая индексация по фрагментам **не атомарна**: при ошибке позднего фрагмента уже записанные данные могут сохраниться. Точный контракт — в [документации импорта](docs/pcap-import.md).

### Нет PCAP? Сгенерируйте пример

После успешного запуска Compose выполните команду в корне проекта (скрипт **также загружает синтетические данные** в работающий стенд):

~~~sh
APP_ADMIN_PASSWORD=local-admin-change-me python3 tests/smoke_analyst.py
~~~

Для PowerShell:

~~~powershell
$env:APP_ADMIN_PASSWORD = 'local-admin-change-me'
python tests/smoke_analyst.py
~~~

Если изменяли `.env`, укажите свой пароль администратора. Скрипт создаёт **`tests/browser_retry.pcap`** — загрузите его через браузер. Используются только зарезервированные тестовые адреса, захвата реальной сети нет. Проверяются 2 подходящих пакета, случай с 102 пакетами на границе фрагментов, корректный файл без совпадений и ошибки с повтором. Этот сценарий проверен в **Linux CI**; приведённая команда для Windows не является заявлением о самостоятельном Windows E2E.

## 4. Просмотр TCP-потоков

Откройте **«Потоки»**. В таблице доступны время начала/завершения, **источник и назначение** (MAC, IP, порт), число пакетов, протоколы прикладного уровня, **SNI (если есть)**, **Sensor ID** и отпечаток. Для поиска есть фильтры по дате, IP, MAC и портам источника/назначения, затем кнопка **«Поиск»**.

Исходный PCAP декодируется одним проходом TShark с сохранением разных идентификаторов `tcp.stream` даже при внутреннем разбиении записи на фрагменты. **Количество проиндексированных наблюдений не равно общему числу пакетов PCAP.**

Если отпечатка нет, интерфейс может показать **«Не определен»**. Пассивный фингерпринтинг — вероятностный вывод по признакам, **не гарантия** точного определения ОС или приложения. Пустой список потоков после результата 0 — нормален; после положительного импорта проверьте фильтры по времени и адресам.

## 5. Статистика и отпечатки

Откройте **«Статистика → По клиентам»** либо **«По серверам»**. Выберите запись для просмотра доступных **TCP-, TLS- и HTTP-отпечатков** и связанных потоков. Возможны статусы **«Не определён»** или **«Обнаружено несколько совпадений»**. Это сводка по сохранённым наблюдениям, а не активное сетевое сканирование и не подтверждение точной версии программ.

При необходимости можно открыть **Kibana** на **http://127.0.0.1:5601**: Compose автоматически создаёт представление `packets-*`. Для обычной работы через Analyst Kibana **не нужна**; её учётные данные Elasticsearch отличаются от логина Analyst.

## 6. Необязательный Sensor — только Linux

В стандартном профиле Sensor **не запускается**. Только на **Linux-хосте** подготовьте `.env` из `.env.example`, укажите в `SENSOR_INTERFACE` реальный разрешённый к захвату интерфейс (проверьте `ip link`), задайте новые секреты и выполните:

~~~sh
docker compose --profile capture-linux up -d --build
docker compose --profile capture-linux logs --tail=100 sensor
~~~

Sensor использует сеть хоста и привилегии `NET_RAW`/`NET_ADMIN`, отбирая наблюдения для Elasticsearch. В Docker Desktop на Windows/macOS **нет эквивалентного доступа** к физическому интерфейсу хоста. Linux CI проверяет **синтетическую** индексацию Sensor→Elasticsearch, а не полноценный захват с физической сети. Для кроссплатформенного сценария используйте импорт PCAP.

## 7. Диагностика

| Проблема | Что проверить |
| --- | --- |
| Не открывается Analyst | `docker compose --env-file .env.example ps -a`, затем `docker compose --env-file .env.example logs --tail=100 analyst postgres elasticsearch kibana elastic-init kibana-init` |
| Elasticsearch не становится healthy | Память Docker, Linux `vm.max_map_count >= 262144`, права на тома и логи Elasticsearch |
| Порт занят | Свободны ли 3000/5601/9200; поменяйте нужный `*_PORT` в локальном `.env` и откройте новый порт Analyst |
| Windows не скачивает образы | Linux-контейнеры в Docker Desktop и настройки сети/прокси системы; это не обязательно ошибка приложения |
| Не подходит пароль `admin` | Возможно, том `postgres-data` уже содержит другого пользователя/пароль; смена переменной окружения не сбрасывает пароль |
| HTTP 403 при управлении пользователями | Ожидаемый запрет для неадминистратора; обратитесь к администратору |
| Результат импорта 0 | Файл корректен, но не содержит выбранных TCP/TLS/HTTP-наблюдений; попробуйте синтетический пример |
| Ошибка импорта | Проверьте `.pcap` и лимит 10 МиБ, затем логи Analyst. Часть ранних фрагментов могла уже сохраниться при поздней ошибке |
| Потоки не видны | Сбросьте фильтры по дате/адресам и проверьте положительное число проиндексированных пакетов |

Если создали `.env`, команды выполняются без `--env-file .env.example`. Подробности: [эксплуатация Docker](docs/docker.md), [API импорта](docs/pcap-import.md), [состояние безопасности](docs/SECURITY_AUDIT.md).

## 8. Остановка и сохранение данных

~~~sh
docker compose --env-file .env.example down
~~~

Остановка **не удаляет** именованные тома `postgres-data` и `elasticsearch-data-v8`. **Не запускайте `docker compose down -v`, если не хотите намеренно уничтожить сохранённых пользователей и индексированные пакеты.** Миграция старых данных Elasticsearch 7 → 8 не реализована.

## Проверенные платформы и границы безопасности

В Linux GitHub Actions проверяются Compose/PostgreSQL, API Analyst, **настоящий Chromium** с загрузкой PCAP и синтетический Sensor→Elasticsearch. Windows/macOS Docker Desktop описаны как варианты запуска, но **не** как независимо принятые сквозные E2E. Реальный захват интерфейса, миграция ES7, нагрузка и защищённое production-развёртывание не подтверждены. В серверных зависимостях остаются уязвимости, включая критический путь TypeORM и проблемы Nest/Axios; во фронтенде остаются устаревшие зависимости. Сохраняйте публикацию сервисов **только на loopback**, не открывайте демонстрационные пароли и HTTP-сервисы в интернет.
